# 云服务中的 Agent 与 Skills 设计

- 状态：讨论稿 v1。本文讨论好运TV产品内的 Agent Skills 如何参与云服务功能，不是 Claude Code 项目指令，也不是已经上线的能力。
- 关联：[产品需求](../requirements/001-wechat-auth-hosted-model-service.md) · [架构方案](../technical/cloud-service-architecture.md) · [技术设计](../technical/cloud-service.md) · [现有技能格式与执行规则](../content/docs/plugins/skills.mdx)。

## 1. 定位

Skills 是可版本化的流程说明和领域知识，指导 Agent 使用 LuckyTV 已授权的工具；Skill 本身不构成账号权限、支付授权或服务端安全边界。

微信身份校验、支付验签、额度计算/扣减、模型供应商密钥访问和账本写入属于服务端领域能力，不得交给 Markdown 指令或 Skill 脚本实现。Agent 只能调用后端明确暴露、按账号授权且带参数校验的业务工具。

## 2. 首期建议边界

- 首期可提供非交易型辅助 Skills：模型选择说明、生成参数解释、任务状态查询说明、费用预估解释、订单/额度查询说明、创作流程模板。
- AI 可根据用户请求生成草稿，例如分镜、提示词、工作流计划；应用具体提交前由真实工具和服务端合同校验。
- 支付下单可以由用户在明确确认后通过正式 UI/API 完成；Agent 不可自行确认支付、伪造支付回调或确认到账。
- Agent 不可自行执行退款、调整额度、修改模型价格、绑定/解绑账号、切换云账号或访问其他账号任务。
- 托管模型任务必须走与非 Agent 请求相同的服务端授权、额度预留、幂等和结算路径；不能因调用来源是 Agent 而绕过规则。

## 3. 工具分级

| 等级 | 示例 | 执行条件 |
| --- | --- | --- |
| 只读 | 查询模型目录、当前额度、本人订单状态、本人任务状态 | 服务端认证并按账号范围过滤；返回最少必要字段 |
| 草拟 | 生成提示词/分镜计划、解释估价、整理创作步骤 | 结果先作为草稿呈现，不产生支付/生成/持久化副作用 |
| 付费提交 | 创建托管模型任务、创建支付订单 | 展示模型、输入摘要、预计/上限费用与额度变化；用户明确确认；服务端重新校验并幂等执行 |
| 高影响管理 | 退款、调账、价格变更、身份绑定/解绑、封禁 | 不向普通 Agent 暴露；由受控管理界面/后台权限执行并审计 |

确认 UI 只表达用户意图，不能代替服务端授权；确认内容应绑定具体账号、动作、模型/商品、参数摘要、额度上限和短期有效的一次性授权引用，修改关键参数后需重新确认。

## 4. Skill 包设计规范

继续遵守 LuckyTV 现有 Agent Skills `SKILL.md` 格式，并采用渐进加载：

- `SKILL.md` 前置 metadata 只写名称与清晰的触发场景；主体写短步骤、工具选择和结果验收。
- 长协议、模型比较、产品规则放在 `references/`，按需加载；避免把全部 API/账务规则复制进 Skill，领域权威仍是服务端代码与正式文档。
- 每个 Skill 声明所需工具、读写范围、是否可能触发费用、需不需要用户确认、失败如何处理、预期输出。
- Skill 不得要求模型索取或显示密码、验证码、OAuth code、支付凭据或完整密钥；不得把系统提示词当权限校验。
- 脚本默认关闭或逐次确认。自动执行开关不能授予支付、调账、退款、外部发布或任意云账号操作能力。
- 远程 Skill 安装需校验来源、版本和内容完整性；升级以固定版本运行，更新不改变进行中的轮次。市场投稿和安装仍使用当前产品确认/审查流程。

推荐 Skill 的说明块：

```yaml
name: hosted-model-guide
description: 帮助用户理解好运TV托管模型、费用估算与任务状态；只在用户询问托管模型选择或费用时使用。
```

正文可按“先读取可用目录 → 说明差异和估价来源 → 展示费用/额度影响 → 需要付费时调用正式确认 UI/API → 汇报服务端任务状态”组织；不能直接调用支付或账本管理接口。

## 5. 服务端工具合同

- 工具名称和 JSON Schema 由服务端注册表维护，前端/Agent 不得通过任意函数名调用内部方法。
- 每个工具需声明 `read`、`draft` 或 `write` 类别、作用对象、用户授权要求、是否收费和幂等语义。
- 工具执行时使用认证上下文中的 account ID；不得信任模型传入的 `accountId`、权限、价格、余额或供应商密钥。
- 写操作必须验证对象归属、业务状态、额度与确认授权；幂等键由宿主/服务端生成或受控解析。
- 返回值只包含工具完成下一步所需的数据；支付/身份/任务状态以服务端状态查询为准。
- 工具错误使用稳定机器可读 reason，并过滤供应商内部地址、认证头、敏感响应正文和凭据。

## 6. 可观测与评估

- 记录 Agent 回合、Skill 版本、工具名、授权等级、结果分类、任务/订单引用与追踪 ID；不记录完整提示词、凭据或敏感支付数据，除非有明确必要性与保留策略。
- 自动化评估覆盖：只读操作无副作用；用户未确认时付费调用被拒绝；确认后参数变更需重新确认；跨账号对象拒绝；模型伪造成功不能改变服务端账本；Skill 指令不能提升工具权限。
- 以真实业务服务合同和权限测试为准，不用源码字符串测试保证 Skill 安全。

## 7. 待讨论

1. 首期是否需要 Agent 直接提交托管模型生成，还是先仅给目录、估价和任务查询工具？
2. 付费操作统一复用画布现有确认 UI，还是增加云额度专用确认步骤？
3. 云端 Agent 是否复用现有 Durable/pi 宿主，或首期完全不做云端 Agent？建议不因登录/计费立项顺带迁移 Agent 执行运行时。
4. Skill 市场是否仅本地安装与版本同步，还是需要云账号关联；是否完全不涉及付费权益？
5. 日志、对话记录和素材引用是否留在本地；若上传云端，需独立隐私与保留需求。
