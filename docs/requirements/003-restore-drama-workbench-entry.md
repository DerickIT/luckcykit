# 恢复短剧项目工作台入口

- 编号：`003`
- 状态：实施中
- 创建时间：2026-11-19
- 关联需求：[当前产品需求基线 BR-017、BR-051](002-current-product-baseline.md)

## 1. 背景与问题

短剧项目列表、创建和详情页面及本地项目 API 已存在，但当前普通导航没有入口，且旧 `/projects/:projectId` 本地兼容路由会把参数解释为画布 ID 并重定向到 `/canvas/:projectId`。因此短剧项目实体不能通过该旧路径安全承载，短剧 UI 流程不可达。

## 2. 目标与非目标

### 目标

- 恢复独立短剧项目列表/创建入口和详情工作台。
- 侧栏与命令面板分别提供“短剧项目”和“画布库”入口。
- 确保短剧项目 ID 与画布 ID 使用不同路由空间。

### 非目标

- 不重做项目 API、数据模型、页面流程或画布库。
- 不恢复云端项目同步或 hosted 产品能力。
- 不改变首页最近画布与其“查看全部”行为。

## 3. 用户场景与需求

- 作为短剧创作者，我希望从全局导航打开短剧项目列表、创建项目并继续编辑章节和分镜，以便在独立于普通画布的项目工作台中完成制作。
- 作为画布用户，我希望画布库的旧入口和兼容链接保持可用，以便既有画布工作流不受影响。

## 4. 范围与边界

- 涉及页面/服务/数据：React Router、短剧列表与详情 UI、侧栏、命令面板、项目画布关联链接、本地网络审计和产品需求基线。
- 外部系统或依赖：已有 Go 本地项目 API；AI 大纲依赖用户配置的文本模型。
- 权限与数据归属：项目读写继续使用现有本地 workspace API 与服务端 feature gate；前端 gate 不替代后端校验。
- 明确不改变的现有行为：`/projects`、`/project`、`/canvas` 的画布行为；首页最近画布；旧 `/projects/:id` 与 `/project/:id...` 画布兼容重定向。

## 5. 验收标准

- [ ] `/dramas` 可显示短剧项目列表，空白项目创建后进入其详情。
- [ ] `/dramas/:projectId/...` 可进入详情的概览、章节、工作流、项目画布、剪辑、资产和设置视图，且不重定向为画布。
- [ ] 侧栏和命令面板均提供“短剧项目”到 `/dramas` 及“画布库”到 `/project` 的独立入口，并正确显示当前选中项。
- [ ] 详情内项目链接和画布项目上下文链接使用短剧路由；打开画布仍使用 `/canvas/:canvasId`。
- [ ] 关闭 `shortDramaEnabled` 时短剧列表和详情被功能门禁拦截；后端 API 仍是权威门禁。
- [ ] `/projects`、`/project`、`/canvas`、首页画布跳转及历史本地画布详情别名保持原行为。
- [ ] 本地网络审计验证新短剧流程只访问允许的本地 API，不触发远端用户数据同步。

## 6. 约束与决策

- 已确认决策：短剧与画布两个入口都保留；短剧专用路由采用 `/dramas`；既有画布 URL 保持兼容。
- 待确认问题：无。
- 兼容性/迁移约束：不迁移 ID 或持久化数据；旧画布路径语义不变。
- 安全、隐私、费用、频率或合规约束：短剧项目请求继续经过后端本地 workspace 和已有 feature gate；不增加远端同步。
- 依赖或禁止事项：不修改数据库/API 合同，不将画布 ID 当作短剧项目 ID。

## 7. 技术方案

### 职责与数据流

`/dramas` 加载既有短剧列表页，详情路由 `/dramas/:projectId/*` 加载既有详情页；两个路由使用 `RequireFeature(shortDramaEnabled)`。页面调用现有 `/api/projects/*` 本地项目 API。旧 `/projects/:id` 和 `/project/:id...` 仍经过现有本地画布兼容处理。

### API / 数据 / 配置变更

- API：无。
- 数据库迁移：无。
- 配置与部署：无。
- 文档：更新当前基线和本需求的验证记录。

### 失败、权限和恢复

列表/API 错误沿用现有页面错误状态；功能关闭时由 `RequireFeature` 提示并提供返回创作台入口。后端 `RequireFeature` 继续执行权威校验。
